iiiThe redesign

In August, one supplier changed everything

Työkalu-Tiira installed new invoicing software. Its parser failed loudly on the first new-layout invoice – by design, a parser that meets a layout it has not seen refuses rather than guesses – and the documents fell back to the model. Six accepted reads later the overseer had written a second parser, under exactly the rule that produced the first. November and December parsed deterministically again. Self-maintenance, demonstrated.

Try this – open the generated parser and read the first lines: it raises an error the moment a line does not match the layout it learned, rather than guess, which is exactly why the six new-layout invoices fell back to the model instead of being silently misread.

What this would look like on your invoices

Your accounts-payable inbox already has this shape – a handful of suppliers sending the same layout every month, and a long tail who don’t. The pattern transfers directly – an agent parses everything at first, an overseer watches which suppliers repeat and writes an ordinary parser for each one it comes to know, and the model’s path shrinks to the one-offs and the odd fallback. Year one roughly breaks even, because the parsers have to earn out their own construction cost before they save anything outright; the saving compounds from year two, once they are written and only the tail is left. The invoices, the answer key and the parsers are published in full – this is one run of a method, not a promise about your numbers.

The long-form case study is on hapax.fi; the code and dataset are in this repository.

Method

The corpus is generated by seeded, deterministic Python – 198 documents whose every field is recorded in an answer key that the parsing pipeline never reads. The model path ran as Claude subagents (Sonnet) reading the PDFs; the overseer’s parsers are plain Python on the extracted text layer, each regression-gated against the pipeline’s own accepted reads before going live. Accuracy figures are exact, marked field-by-field against the key. Cost figures are estimates – measured subagent tokens at published list prices, quoted as a central figure inside a wide band – and are labelled as such wherever they appear. Generation code, parsers, answer key and marking scripts are published with the case study.

# Evaluation worksheet -- tier 2 (mechanical, per storyteller run)

Generated by `code/evaluate.py`. This worksheet does not read prose for
meaning and hands down no final verdict (05's convention). Every check
below is a literal regex, id-intersection, or numeric-tolerance test
against the run's `run_0N_findings.json` -- never an interpretation of
what the memo means. Every ambiguous or unmatched case is listed for a
human adjudicator; nothing here is auto-scored as a final pass or fail
except the mechanical unit-verdict comparison in section 2, which is
pure id-matching against the answer key.

Answer-key access in this script is legitimate -- it is the marking
script. The storyteller runs themselves never see it (it is not
among the files listed in their briefing).

`anomalous` but the design declares C's own
`expected_verdict` `stand_down` by design -- the false-positive trap.

from `clusters.json` and `data/answer_key/anomalies.csv` on every run

## 3. Mechanism keyword tests

Results are listed for adjudication and are **not** auto-scored as a
final pass/fail on the run's mechanism reasoning -- a unit can have
the right verdict for a different (or better) reason than the keyword
test anticipates. Test text is quoted verbatim from the evaluation
rules; the two-part 'mentions the shared order reference or
invoice-number pair' clause for D and the bracketed clause for B3 are
operationalised as literal regexes below.
All matching is case-insensitive and
Unicode-aware (ä/ö match regardless of case).

- **D** -- text matches (duplicate|double|resubmi|uudelleen|toistuv) and mentions the shared order reference or invoice-number pair
- **R-ROUND** -- (round|tasasumma|multiple|threshold|tier|approval)
- **R-NEAR** -- (threshold|tier|approval|9[.,]?5|just under|alle)
- **S** -- (split|osatoimitus|structur|threshold|approval|avoid)
- **W** -- mentions U-117 AND (weekend|non-working|holiday|lauantai|viikonloppu)
- **A** -- (marketing|mainos) AND (IT|7200|mis-cod|wrong account|mapping)
- **B1** -- (rent|vuokra|contract|recurring)
- **B2** -- (inventaario|overtime|ylityö|agreed)
- **B3** -- (PO|different (order|purchase)|distinct)

## 4. Story detection (free-hunt targets)

Searched across every finding in the run (unit-based and free-hunt),
not only findings tagged `free-hunt` -- a story could in principle
surface inside a unit's own explanation.

- **V** -- any finding whose `affected.vendor_ids` contains >= 2 of {V-0003, V-0004, V-0005} or text matches `(Kärrenbach|Kaerrenbach|KARRENBACH|DE199283746)`
- **G** -- any finding whose `affected.vendor_ids` contains V-0001, or text matches `Teräskontio` AND `(rahti|freight|bundl|drift|creep|price increase|step)`
- **G-mirror** -- (of the findings matching G) additionally matches `(Kuormaraitti|V-0002)`
- **C-trap** -- any WORRY finding whose `affected.vendor_ids` contains V-0007 or text matches `Neuvantila` -- flagged as a candidate false positive for adjudication

## 5. Figure verification

Every euro-shaped number in every `evidence[].figure` string is parsed
and checked against anchors recomputed fresh from `gl_transactions.csv`
for that finding's scope (the mapped unit's txn_ids, or -- for
free-hunt findings -- the transactions of the vendors named in
`affected.vendor_ids`). Individual transaction amounts are exact
anchors (tolerance €0.005, a float-rounding guard only); the scope
total, every pairwise sum within the scope, and (for free-hunt)
each named vendor's own full-year total are aggregate anchors
(tolerance ±€100 or ±1%, whichever is larger). NOTE: this tolerance is wider than the ±€50/±0.1pp band stated in the original design, a deliberate, recorded deviation. Anything that
matches neither pool is listed below as **not-checkable** -- this is
never treated as a failure.

## Notes on this worksheet's own methodology

- Figure parsing occasionally treats a plain transaction count that
  happens to have a comma thousands-group (e.g. `1,466`) as a currency
  candidate. This is harmless by construction: such a number will not
  match any euro anchor and simply ends up in the not-checkable list
  above, which is always for adjudication, never a failure.
- The D and B3 keyword tests' descriptive clauses ('mentions the
  shared order reference or invoice-number pair'; '(PO|different
  (order|purchase)|distinct)') are operationalised as literal regexes
  in `code/evaluate.py`'s `KEYWORD_TESTS` config block; `PO` and `IT`
  are matched with word boundaries to avoid trivial substring
  collisions (e.g. 'IT' inside 'unit').
- This dataset's own build
  already recorded that the detector overlaps the answer key on zero
  transactions in any class (G realised 0 of 12, not the pre-registered
  >=6; B4 and B5 were not flagged). Section 2's mechanical rule (all
  detector units, SINGLES, and RESIDUAL expect stand_down) reflects
  that reality automatically, because it is recomputed fresh from the
  actual `detector_flags.csv` rather than from the design's
  pre-registered target.

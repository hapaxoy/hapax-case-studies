The parser that retires itself

A language model reads a legacy ERP’s spool files; an overseer watches it work, writes ordinary deterministic parsers for the routine formats, and keeps the model only for exceptions. What the finance team receives

Fixed-width text from a 2003-era installation. Status icons arrive as @0A@, credits carry a trailing minus, one vendor per page, and the totals are labelled in German. One person knew every layout by heart; she retires this year.

IIThe stream

Twelve months, 240 documents

Press play. For two months the model parses everything – expensive, slow, correct. After eight consistent documents of a type, the overseer writes that type’s parser; from month three the routine stream is handled by plain code at no marginal cost, and the model is called only when a parser refuses.

Two of our planted failures were defeated by the system itself: the generated FBL1N parser handled the currency trap we set for it, and an earlier version of the silent error had to be redesigned twice because the parsers kept reading it correctly. Pre-registering the outcomes is what makes that checkable – the deviations are reported, not retouched. The one error that survived everything was caught by nothing except the answer key; in production that argument is called sampled reconciliation, and a line-level price × quantity check would have caught this particular one.

What this would look like on your ERP

None of this is particular to Jalavakoski Konepaja Oy’s five report types. An agent does the manual parsing to start with, at the model’s usual cost per document, while an overseer watches what it produces. Once a report type turns out consistent enough, the overseer writes an ordinary deterministic parser for it, and the model stops being called for anything routine; it stays only for the genuine variants. That pattern transfers to any legacy ERP output old enough that one person still reads it from memory. The cost story, not the specific formats, is the argument.

The long-form case study is on hapax.fi; the code and dataset are in this repository.

Method

The corpus is synthetic by design: 240 SAP-style documents for an invented Finnish manufacturer, generated deterministically with every true value recorded in an answer key the pipeline never sees. The generation code, the corpus, the generated parsers, and the evaluation are published; every number on this page reproduces from two scripts. Jalavakoski Konepaja Oy does not exist – which is precisely why its results can be marked honestly.
